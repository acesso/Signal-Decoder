FT8 LDPC decode: WebGPU parallel vs CPU/WASM feasibility benchmark

Loads 19 real LLR arrays captured from ft8mon's own successful decodes (all ldpc_ok=83, CRC-valid), synthetically replicates them up to a target candidate count, and runs LDPC belief-propagation 2 ways: (1) plain-TS CPU reference (ldpcDecode.ts, one candidate at a time, sequential — same shape as ft8mon's own per-candidate loop), (2) WGSL GPU kernel (ldpcDecode.wgsl, ALL candidates dispatched in parallel, one GPU invocation each). Verifies every candidate's decoded output matches the real ft8mon-captured answer before reporting timings. Note: the current scratch-buffer layout puts one m/e block per candidate in a single storage buffer, which hits WebGPU's 128 MiB default maxStorageBufferBindingSize around ~1161 candidates on most devices — past that, runLdpcDecodeGpu throws a clear error instead of the silent all-zero corruption this used to produce.
