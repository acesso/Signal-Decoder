Wi-Fi network

Saves to the bridge's own storage and reboots to join the new network. You'll need to reconnect at the new address (or usdx-bridge.local once mDNS updates). If the new network can't be reached, the bridge falls back to broadcasting its own "usdx-bridge-setup"-style access point at 192.168.4.1 so you can fix it here again.

Radio firmware

Running
—

Updates the uSDX over the CAT line (Optiboot 8 bootloader, entered with UG;): every page is written, read back and compared, then the radio restarts. EEPROM is not touched — settings survive. CAT is paused for the ~25 s it takes. Refused while the radio is keyed or the external PA reports energized. If an update fails part-way the radio needs the ISP cable.

System

ALC

The ES8388's Automatic Level Control — confirmed off by the chip's own power-on-reset default and never touched by firmware, but exposed here as a checkable diagnostic. Not persisted; resets to Off after a reboot regardless.

Noise gate

Part of the ALC block above — only has an audible effect while ALC itself is also on. Same off-by-default, not-persisted caveats.

Status LEDs

Turns the status LED off and on, for example to check whether its switching adds noise to the audio path. Not saved: the LED is back on after a reboot.

CPU frequency

Pins the ESP32's CPU clock (no dynamic scaling either way) — a low-confidence experiment for whether digital switching activity couples into the analog audio path. Not persisted; reverts to 240 MHz (the board's boot-time default) after a reboot.

WiFi TX power

Live-sets the WiFi radio's max transmit power — a low-confidence experiment for whether the radio's own transmit activity couples noise into the analog audio path. Applied immediately AND persisted to NVS — lowering it may weaken WiFi range/reliability, so raise it back if the connection gets flaky.

Diagnostic — live audio test

idle

Tunes the bridge → radio audio path against what the radio's mic ADC actually receives, without transmitting. In diagnostic mode the radio keys normally but sends nothing to the HF line (no PA drive, no TX clock, external amp never keyed, TX time-out off) and shows D instead of T. The live test plays the bridge test tone, keys a dry TX and plots every ~0.5 s window the radio reports. The graph holds only the current run; Start clears it.

TX cache

—

The four TX audio buffer slots (POST /tx-audio), each holding one pre-encoded message the device plays back from its own PSRAM on POST /tx-play — uploading the whole message up front is what keeps Wi-Fi jitter out of the transmitted signal. The message text and audio Hz shown here are metadata the uploader supplied alongside the audio; the device stores them verbatim and never interprets them (the Hz is already baked into the samples themselves). Slot 0 is the standing auto-CQ waveform, 1–2 the head of the web app's TX queue, 3 spare.

▶ Play always plays the slot on the bridge DAC, into the radio's mic input — on its own that never transmits (the radio has no VOX). With Auto-PTT the page keys the radio around it: checks the radio is in LSB/USB, sends TX;, waits the pre-key time, plays, waits for the end and the post-key time, then RX; — Stop and any error always send RX;.

CAT monitor

Hide
◀ RADIO from the radio ▶ BRIDGE sent from this bridge page ▶ APP sent by another client (web app)

Live sniff of every CAT frame crossing the bridge in either direction. Quick-command chips are the read-only queries the radio lists (CL;) — never TX, restart or any SET. Clicking a chip adds it to the command line; chain several, edit, then Send. After every SSB transmission the radio reports what its mic input received (TA); this page evaluates it into the panel above. Connects to the same /cat WebSocket the web app uses, so this is exactly what it sees. The baud rate here must match the radio's own CAT menu setting (there's no CAT command that reports or changes it, so if you change it on the radio, change it here too).

Persisted log

Survives reboots — a flash-backed ring buffer of the most recent 1000 frames, unlike the live log above which is lost the moment this tab closes or the bridge restarts. Meant for answering "what was the radio doing right before a restart"; "Load" fetches it on demand rather than auto-refreshing.

Persisted log enabled

Off by default — a debug feature. Its boot-time flash-recovery scan grows with the log's own record count and was found to push the bridge's boot past the 5s task-watchdog timeout on real hardware, causing a crash-loop. Changing this saves the setting and reboots the bridge.
