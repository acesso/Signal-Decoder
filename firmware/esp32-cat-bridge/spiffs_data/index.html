System

ALC

The ES8388's Automatic Level Control — confirmed off by the chip's own power-on-reset default and never touched by firmware, but exposed here as a checkable diagnostic. Not persisted; resets to Off after a reboot regardless.

Noise gate

Part of the ALC block above — only has an audible effect while ALC itself is also on. Same off-by-default, not-persisted caveats.

CPU frequency

Pins the ESP32's CPU clock (no dynamic scaling either way) — a low-confidence experiment for whether digital switching activity couples into the analog audio path. Not persisted; reverts to 160 MHz after a reboot.

WiFi TX power

Live-sets the WiFi radio's max transmit power — a low-confidence experiment for whether the radio's own transmit activity couples noise into the analog audio path. Applied immediately AND persisted to NVS — lowering it may weaken WiFi range/reliability, so raise it back if the connection gets flaky.

"Speaker" streams raw audio over a second WebSocket (/audio), independent of the CAT connection. "Mic → Radio" is a read-only tap on the exact samples the bridge just wrote to the radio's mic input (/audio-mic-sniff) — since the web app's mic-send path has no return signal at all, this is the only way to confirm audio actually reached the radio and hear/see what it sounded like. Both are independent and can be on or off in any combination; the sniffer can never affect or slow down the real mic-send path. For tuning the interface board's audio-in/audio-out RC filter trimpots by eye — the horizontal blue dashed line marks the estimated passband rolloff amplitude (~-6dB below peak); watch it move as you adjust each trimpot.

ADC input

Which physical input path the ES8388 codec reads from. Confirmed via a known-good phone line-out test: LIN2 is the P2 jack and sounds best of the 5 — the others are mostly for reference/comparison now.

ADC RX channel

A SEPARATE axis from ADC input above — once a physical input is selected, this picks which of its two ADC channels (left/right) the ESP32 actually keeps. A jack's tip signal can land on either one depending on board wiring. Switching pauses capture briefly.

MIC PGA gain 0 dB

0dB (unity gain) is the ES8388's own PGA default. The onboard mic capsule was found bleeding audibly into every ADC input mode (a board-wiring issue, not fixable by any register here) — raising or lowering this won't fix that bleed, only the overall input level.

Status LEDs

One-time reversible test: does the LEDs' own PWM switching (right next to the codec on this board) inject noise into the audio path too? Toggle off, listen for a change, toggle back — not persisted, resets to On after a reboot regardless.

ADC high-pass filter

On (removing DC offset) is the ES8388's own power-on-reset default — unlike ALC/noise gate above, this one starts ON, not off. Exposed so it can be turned off to compare while chasing a reported broadband noise floor that shows up even on a clean sine wave from a known-clean source.

Speaker amp (NS4150)

Forces the onboard NS4150 speaker amp's own enable/shutdown GPIO directly, bypassing the codec driver. A class-D amp has its own free-running switching oscillator — a real on-board noise source. The enable pin's polarity was only ever a guess, never confirmed — toggle both ways and listen/measure to see which one actually silences it, and whether it changes the line-in noise floor at all. Not persisted; resets to On after a reboot regardless.

Input mode

Audio is the original, long-proven mode: the line-in jack carries already-demodulated SSB/audio, captured mono, broadcast on /audio. I/Q is for a radio that instead puts raw in-phase/quadrature (pre-demodulation, wideband) on the SAME jack — I on the left ADC channel, Q on the right — captured as true stereo and broadcast on the separate ws://<device>/iq-data instead. Changing this saves and reboots the bridge to apply. Switching to I/Q forces the ADC RX channel row below to both-Left-and-Right (it needs both channels at once, not a choice between them) and unlocks 96kHz on the Sample rate row.

Sample rate

The /audio (or /iq-data, in I/Q mode) WebSocket's wire rate, which IS the codec/I2S hardware's own sample rate too. Defaults to 48kHz to match a typical laptop sound card, so A/B comparisons against a direct sound-card capture aren't also comparing two different rates. 96k is only available in I/Q mode and switches the ES8388 into double-speed mode — genuinely less proven than the other rates (see the Known Limitations note in the README); 48k is a safe fallback if it doesn't clock cleanly on your board. 22.05k and 44.1k are disabled in I/Q mode — real-hardware captures showed unique, reproducible spectral artifacts at exactly those two rates, not present at any other rate; still available in Audio mode. Changing this saves and reboots the bridge to apply — not a live switch, unlike the other controls on this page.

CAT monitor

Live sniff of every CAT frame crossing the bridge in either direction — ← from the radio, → to the radio. Connects to the same /cat WebSocket the web app uses, so this is exactly what it sees. The baud rate here must match the radio's own CAT menu setting (there's no CAT command that reports or changes it, so if you change it on the radio, change it here too).

Persisted log

Survives reboots — a flash-backed ring buffer of the most recent 1000 frames, unlike the live log above which is lost the moment this tab closes or the bridge restarts. Meant for answering "what was the radio doing right before a restart"; "Load" fetches it on demand rather than auto-refreshing.

Persisted log enabled

Off by default — a debug feature. Its boot-time flash-recovery scan grows with the log's own record count and was found to push the bridge's boot past the 5s task-watchdog timeout on real hardware, causing a crash-loop. Changing this saves the setting and reboots the bridge.
